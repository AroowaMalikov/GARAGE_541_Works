# 📖 README

Данный проект представляет собой набор скриптов для экспериментального исследования вычислительной сложности структур данных (списков и множеств) на языке Python.

## 📂 Структура проекта и назначение файлов

Проект состоит из трех основных скриптов-экспериментов и одного скрытого файла зависимостей.

### 1. `experiment_lists.py` (Задание 2.1)
**Назначение:** Сравнение производительности списков на базе массива и двусвязного списка.
**Что делает:**
* Замеряет время выполнения базовых операций: `append` (в конец), `insert` (в середину), `get` (чтение из середины), `remove` (удаление из середины).
* Сравнивает **самописные** структуры (`ArrayList`, `DLinkedList`) со **встроенными** аналогами Python (`list` и `collections.deque`).
* Для чистоты эксперимента каждая операция усредняется по `CALLS` запускам.

### 2. `experiment_sets.py` (Задание 2.2)
**Назначение:** Исследование множеств на базе упорядоченного (`SortedArraySet`) и неупорядоченного (`UnsortedArraySet`) массивов.
**Что делает:**
* Генерирует серии запросов (add, remove, contains) с помощью **собственного ГПСЧ** (`weighted_query`), который позволяет задавать точные доли (вероятности) каждой операции.
* Тестирует структуры на разных размерах (`SIZES`) и при разных профилях нагрузки (`MIXES` — например, 80% добавлений и 10% удалений).
* **Гарантия честности:** Перед каждым запуском структуры вызывается `seed(42)`, что гарантирует, что `SortedArraySet` и `UnsortedArraySet` получат *абсолютно одинаковую* последовательность запросов.

### 3. `set_ops.py` (Задание 2.3)
**Назначение:** Парсер и исполнитель операций над множеством из строки специального формата.
**Что делает:**
* Принимает строку вида `a5add-7r10contains5` или `file:ops.txt`.
* Разбирает строку на пары `(операция, значение)`, поддерживая как короткие (`a`, `r`, `c`), так и длинные (`add`, `remove`, `contains`) коды, а также отрицательные числа.
* Выполняет операции над `UnsortedArraySet` и выводит понятный человеку результат (например: `5 добавлен, -7 не найден`).

### 4. `structures.py` (Зависимость)
*Файл не предоставлен в задании, но подразумевается.* В нем должны лежать классы: `ArrayList`, `DLinkedList`, `SortedArraySet`, `UnsortedArraySet`.

## Быстрый старт

### Запуск `experiment_lists.py`
```bash
python experiment_lists.py
```
**Важные параметры для настройки (в начале файла):**
* `SIZES = [10**k for k in range(2, 7)]` — размеры списков (от 100 до 100000). *Уменьши до `range(2, 5)`, если самописный `DLinkedList` или `ArrayList` будут работать слишком долго на вставках в середину.*
* `CALLS = 10` — количество итераций для усреднения времени. Увеличь до 50-100 для более точных замеров на малых `N`.

### Запуск `experiment_sets.py`
```bash
python experiment_sets.py
```
**Важные параметры для настройки:**
* `SIZES` — размеры множеств.
* `CALLS = 2000` — количество операций в одной серии.
* `MIXES` — кортежи долей `(add, remove, contains)`. Сумма в каждом кортеже должна быть равна 1.0. Ты можешь добавить свои профили, например `(0.0, 0.0, 1.0)` для теста только на чтение (contains).

### Запуск `set_ops.py`
```bash
python set_ops.py
```
**Варианты ввода:**
1. **Через консоль:** Запускаешь скрипт, вводишь строку, например: `a10a20r10c10c50`. Нажимаешь Enter.
2. **Через файл:** Создаешь текстовый файл (например, `test.txt`), пишешь туда `a5a-7r5c5`. Запускаешь скрипт и вводишь: `file:test.txt`.

### Как работает ГПСЧ в `experiment_sets.py`?
В задании требовалось "разработать свой или адаптировать встроенный ГПСЧ". Ты реализовал очень элегантный метод **инверсного преобразования распределения** (хоть и в упрощенном виде для дискретных событий).
Функция `weighted_query(rng_value, shares)`:
1. Берет одно случайное число `rng_value` от 0 до 1 (генерируется через `random()`).
2. Проходит по долям (`shares`). `border` накапливает сумму долей.
3. Если `rng_value` попадает в текущий интервал `[0, border)`, возвращается соответствующая операция.
*Пример:* Доли `(0.8, 0.1, 0.1)`. 
Если `rng_value = 0.05`, оно `< 0.8` -> `add`. 
Если `rng_value = 0.85`, оно `> 0.8`, но `< 0.9` (0.8+0.1) -> `remove`.
Это работает быстрее и точнее, чем генерировать случайное число для каждой операции отдельно.

### Как работает парсер в `set_ops.py`?
Функция `parse_ops(line)` работает как **конечный автомат с указателем (индексом `i`)**:
1. Указатель `i` стоит в начале строки.
2. В цикле проверяется, начинается ли остаток строки с какого-либо кода операции (`contains`, `add`, `a` и т.д.). Проверяются сначала длинные, чтобы `contains` не截анулся как `c`.
3. Если код найден, указатель `i` сдвигается на длину кода.
4. Далее считывается число: проверяется знак минуса, затем читаются все цифры подряд.
5. Число преобразуется в `int`, пара `(код, число)` сохраняется, и цикл продолжается.
Этот подход отлично справляется с отсутствием разделителей между операциями (например, `a5r-10c7`).

### Архитектура и Workflow
1. **Инициализация:** Скрипты импортируют "чистые" структуры данных из `structures.py`. Это правильный подход (разделение логики данных и логики тестирования).
2. **Подготовка данных:** Структуры заполняются случайными числами (`fill` или предзаполнение в `run_series`), чтобы операции `remove` и `contains` не работали с пустыми коллекциями (иначе замеры будут некорректными).
3. **Замер времени:** Используется `time.perf_counter()`. Это **единственно верный** выбор для Python, так как он имеет максимальное доступное разрешение и не подвержен влиянию системных часов (в отличие от `time.time()`).
4. **Вывод:** Данные форматируются через f-strings с выравниванием (`:<12`), что позволяет получать красивые таблицы прямо в консоли без сторонних библиотек вроде `pandas` или `tabulate`.
